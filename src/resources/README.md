## Reading layouts

Figma nodes 294:1628 (412 x 917) and 328:2068 (1280 x 900).
ReadingPanel scales the complete scene uniformly and omits the Android status bar.
Stationery x/y are the top-left of the rotated Figma bounding box; width/height
are the unrotated content size. Do not rotate around x + contentWidth / 2.
Pencil and lens exports contain 28 logical pixels of shadow overflow; the
highlighter has its original Figma image-fill crop. Transparent stationery
areas pass mouse events through to the illustrations behind them.
Return uses the original ribbon atlas, and the paragraph uses bundled MaruBuri
with 14px line boxes (underlined only in the wide layout). Book title remains
the currently selected book; author/body text are still prototype content.
Resizing snaps between layouts without recentering the window. Return restores
the original main window size and location.

Reading snaps animate for 300ms with smooth acceleration/deceleration. Window
size interpolates without moving its origin, while 2x scene snapshots fade
between the portrait and open-book layouts. Input is suspended during the
transition and restored afterward. Resize events generated by the animation
are excluded from snap detection to avoid recursive transitions.

## Interactive reading tools

Choose pencil/highlighter/pen, then click a sentence. Underlines and highlights
are independent toggles; clicking the same sentence again removes that mark. Pen adds a
memo section beneath the paragraph for that sentence. Enter saves, Shift+Enter
inserts a newline, Escape leaves the draft unsaved. Clicking a saved memo edits
it again. Right-click a memo for Edit/Delete; saving an empty memo deletes it.
Magnifier cycles body and memo text through 18px / 11px / 14px body sizes;
book title and author remain fixed, without changing the annotations.

ReadingDocument stores annotations by book ID and sentence range. Files are
written atomically under ~/.archivefever/notes (override archivefever.notes.dir
for tests). This is local frontend persistence, not a backend integration.
Draft memo text stays in memory until Enter. No real book text/author API has
been connected yet; the current paragraph remains prototype content.

ReadingToolsSmokeTest verifies sentence hit-testing, combined annotations,
Enter save, persistent reload, book isolation, magnifier cycle, scaled clicks,
and preservation across animated layout transitions.

Reading stationery lifts 6 logical pixels only while the pointer hovers over it.
Selection does not change brightness or keep the tool raised. The portrait reading screen no longer paints the tinted wall
layer; wallpaper trim, wood and page assets remain.

## Live camera on the phone

When the UI runs inside the phone app (see backend/README.md and mobile/README.md), the
app draws its live camera picture over the blank display of the camera illustration,
on both camera screens. CameraScanPanel.DISPLAY is that opening in design coordinates;
change it together with the camera artwork.

AppShell tells the host when a camera screen comes into view or is left, and when its
scan button is pressed (HostBridge.showCamera / hideCamera / capturePhoto), so the photo
is taken at the press. On Add book the photo is then uploaded to the server's scan and the
confirmation popup shows the book.

On Archive sentence the scan button asks the host for a page photo (HostBridge.capturePage).
The phone app reads the text on it, on the phone, and lets the reader pick lines on the
picture. The same button, now "save.", asks the host to save them (HostBridge.savePassage):
the app shows the picked text and the page number it found for correction, sends them to
the server, and answers with a PassageResult. Once saved, AppShell opens the book's reading
page. Back (Escape) on a captured page returns to the camera for another photo.

Connected to the server, the reading page of a shelf book shows the passages collected
from it in page order, a paragraph each, with a "p.127" line wherever the page changes
(LibraryController.readingText). ReadingDocument ends a sentence at every line break, so
each passage and page note is marked on its own, and when the text grows the saved marks
follow their sentences to their new places. ReadingText scrolls by drag or wheel once the
text is longer than the page.

On the desktop there is no camera: without a server both screens behave as described
above, and with one (-Darchivefever.api) save opens a dialog to type the passage in.
